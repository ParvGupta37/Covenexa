# Terminology Glossary

| Term | Definition |
|:-----|:-----------|
| **Private Credit** | Loans originated directly by private investment firms (not banks or public bond markets). Also called Direct Lending or Private Debt. |
| **Borrower** | The company receiving the loan. Tracked in Covenexa with a Borrower Health Score, covenants, financials, and risk assessments. |
| **Lender / Organization** | The fund or firm providing the loan. Each Covenexa Organization has one or more Borrowers. |
| **Loan Facility** | The specific credit arrangement — includes principal, interest rate, maturity date, and status (ACTIVE / CLOSED / DEFAULTED). |
| **Loan Agreement** | The legal PDF/DOCX contract governing a Loan Facility. Ingested and parsed by Covenexa's Document Intelligence pipeline. |
| **Covenant** | A contractual rule the Borrower must comply with throughout the loan term. E.g., "Total Debt / EBITDA must not exceed 4.0x". |
| **Financial Covenant** | A covenant tied to a measurable financial metric (e.g., leverage ratio, interest coverage). |
| **Covenant Breach** | When a Borrower's actual metric violates the covenant threshold. Status escalates from `watch` → `breach` → `critical`. |
| **Headroom** | The buffer between the current ratio and the covenant threshold. Lower headroom = higher risk. |
| **EBITDA** | Earnings Before Interest, Taxes, Depreciation & Amortization. A key proxy for operating cash flow. |
| **Leverage Ratio** | Total Debt ÷ EBITDA. Measures how leveraged the borrower is relative to earnings. Covenexa monitors against the covenant limit. |
| **Interest Coverage Ratio** | EBITDA ÷ Interest Expense. Shows ability to service debt. Below 1.5x is a warning signal. |
| **Current Ratio** | Current Assets ÷ Current Liabilities. Measures short-term liquidity. |
| **Borrower Health Score** | Covenexa's 0–100 composite score for a Borrower. Weighted across 5 dimensions: Financial (35%), Compliance (25%), Liquidity (20%), Leverage (10%), Trend (10%). |
| **Default Probability** | AI-estimated likelihood (0–100%) that a Borrower will fail to repay. Computed using Altman Z-Score + financial ratio adjustments. |
| **Altman Z-Score** | A classical financial formula for predicting corporate bankruptcy. Covenexa maps it to a 0–100 default probability scale. |
| **Stress Test** | Simulated scenario where financial inputs (revenue, EBITDA, debt, interest) are shocked by defined percentages to evaluate covenant resilience. |
| **AI Recommendations** | Prioritized action items (CRITICAL / HIGH / MEDIUM / LOW) generated by Covenexa's RecommendationEngine for a given Borrower. |
| **AI Copilot** | Conversational AI interface. Answers natural-language questions about a Borrower using Hybrid GraphRAG — SQL + Vector + Graph context. |
| **RAG** | Retrieval-Augmented Generation. Retrieves relevant data chunks from multiple sources before generating an LLM response. Reduces hallucinations. |
| **GraphRAG** | A RAG variant that also queries a Knowledge Graph (Neo4j) to enrich context with entity relationships — not just text chunks. |
| **Knowledge Graph** | A Neo4j graph database mapping Borrower → Loan → Agreement → Covenant relationships as interconnected nodes and edges. |
| **Vector Database** | Pinecone — stores embedded document chunk representations. Enables semantic similarity search over ingested agreements. |
| **Embeddings** | Dense vector representations of text generated by Cohere Embed v4. Used for semantic search in Pinecone. |
| **LLM** | Large Language Model. Covenexa uses Cohere Command A for all text generation and covenant/financial extraction. |
| **Multi-Agent System** | The AI backend is decomposed into 10 specialized agents (DocumentAgent, CovenantAgent, FinancialAgent, etc.), each owning a single responsibility. |
| **Document Pipeline** | The end-to-end flow from file upload → parsing → chunking → embedding → covenant extraction → financial extraction → risk scoring. |
| **Credit Memorandum** | A formal 6-section credit analysis document generated by Covenexa's ReportingAgent covering financial summary, covenants, stress, and recommendation. |
| **Organization** | A Covenexa tenant — a fund or lender with one or more Borrowers. Admins can create and delete Organizations. |
| **JWT** | JSON Web Token. Used for stateless authentication. Covenexa issues short-lived `access_token` and longer-lived `refresh_token`. |
| **RBAC** | Role-Based Access Control. Covenexa has two roles: ADMIN (full access) and ANALYST (read + upload + query). |
| **Audit Log** | Immutable record of every significant action in the platform (login, upload, deletion). Stored in `audit_logs` table. |
| **Event Bus** | Redis Pub/Sub infrastructure. When a document is uploaded, a `DocumentUploadedEvent` is published and consumed asynchronously to trigger the AI pipeline. |
| **MCP** | Model Context Protocol — tool-calling standard used by Covenexa's MCP Server to expose Neo4j, PostgreSQL, and analytics functions to AI agents. |
